## 命运：边确认即钉死下游可达集合

值班把草稿/已发布边确认成正式关系时，服务端在**一个串行事务**里一次写完选定命运：

- **凭证**：旁路凭证表 `fate_vouchers` 写入确认瞬间可达下游节点清单，拒再改；
- **归档**：归档层独立落一份不可改的闭包物化包 `fate_archives` + `fate_archive_items`。

两条命运**互斥**，本台命运口径在首次确认时锁定（`meta.fate_mode`），之后不可并开。
选定哪条，影响分析就读哪套集合；边列表亮「命运·口径 · N 个下游」芯片，影响页亮
「同源下游」计数。命运索引、凭证清单、归档包、归档清单均有 SQLite 触发器只增不删不改。

**同源闸**：节点目录指纹与闭包清单须同源。确认后若钉住节点的编号/层级/状态在目录里变化，
或闭包清单被改、归档包与索引两源拧了，则影响开跑与入库编排闸口（`/api/orchestration/preflight`）
一并拦下，并在四屏与设置页显示漂移明细。

**并发**：确认走 `BEGIN IMMEDIATE` 串行闸，事务内二次读库判既成命运；两名仓管同时确认同一条边，
只有一人落库，后到者 409「不可再改」，不会各写一份互相覆盖。
